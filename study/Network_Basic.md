시스템 호출 : 커널이 자신을 보호하기 위해 만든 인터페이스. 커널은 사용자나 응용 프로그램으로부터 컴퓨터 자원을 보호하기 위해 자원에 직접 접근하는 것을 차단한다. 시스템 호출을 거치지 않고 커널에 진입 할 수 없음.  
응용 프로그램과 커널의 인터페이스가 시스템 호출이라면 커널과 하드웨어의 인터페이스는 드라이버가 담당. 커널이 제공하는 드라이버도 있고 하드웨어 제작자가 제공하는 드라이버도 있음. 하드웨어는 커널과 직접 연결되기도 하고 하드웨어 제작자가 제공하는 드라이버를 통해 연결되기도 한다.  

API(Application Programming Interface, 응용 프로그램 인터페이스) : 응용 프로그램이 자신과 연관된 프로그램을 만들 수 있도록 제공하는 인터페이스. API는 시스템 호출보다 광범위한 개념. 운영체제의 API를 시스템 호출이라고 정의  
SDK(System Developer's Kit, 시스템 개발자용 키트) : 개발자를 위해 API 및 API 사용 매뉴얼 뿐만 아니라 개발에 필요한 코드 편집기와 에뮬레이터 같은 각종 개발용 응용 프로그램까지 하나로 묶어서 배포하는 개발 툴  

## 커널이 주로 하는 일
- 프로세스 관리 : 프로세스에 CPU를 배분하고 작업에 필요한 제반 환경을 제공
- 메모리 관리 : 프로세스에 작업 공간을 배치하고 실제 메모리 보다 큰 가상공간을 제공
- 파일 시스템 관리 : 데이터를 저장하고 접근할 수 있는 인터페이스를 제공
- 입출력 관리 : 필요한 입력과 출력 서비스를 제공
- 프로세스 간 통신 관리(Inter - Process Communication, IPC) : 공동 작업을 위한 각 프로세스 간 통신 환경을 지원

## 하드웨어의 구성
컴퓨터는 CPU(중앙처리장치), 메인메모리, 입력장치, 출력장치, 저장장치  
메인메모리는 전력이 끊기면 데이터를 잃어버리기 떄문에 데이터를 영구히 보관하려면 하드디스크나 USB를 사용해야 한다. (메인메모리 : 제 1 저장장치, 하드디스크나 USB : 제 2 저장장치)  
CPU : 명령어를 해석하여 실행하는 장치. 메모리는 작업에 필요한 프로그램과 데이터를 저장하는 장소로, Byte 단위로 분할되어 있으면 분할 공간마다 주소로 구분한다.  
GPU : 계산을 필요로 하는 프로그램에 필요. 그래픽용 CPU  
RAM(Random Access Memory, 주기억장치) : 보조기억장치에서 업무를 적재하는 용도로 사용  
HDD : 비휘발성, 순차접근이 가능한 컴퓨터의 보조 기억 장치. 보호 케이스 안에 있는 플래터를 회전시켜 자기 패턴으로 정보를 기록  
SSD : 플래시 메모리로 구성, HDD에 비해 데이터 I/O 속도가 매우 빠름  
HDD, SSD는 보조기억장치  

## CPU의 기본구성
- 산술 논리 연산장치 : 데이터 연산
- 제어장치 : 작업 지시
- 레지스터 : 데이터 임시 보관

버퍼(Buffer) : 속도에 차이가 있는 두 장치 사이에서 차이를 완화하는 역할  
캐시(cache) : 메모리와 CPU간의 속도 차이를 완화하기 위해 메모리의 데이터를 미리 가져와 저장해두는 임시 장소. 필요한 데이터를 모아 한꺼번에 전달하는 버퍼의 일종으로 CPU가 앞으로 사용할 것으로 예상되는 데이터를 미리 가져다놓음.  
병렬처리 : 동시에 여러 개의 명령을 처리하여 능률을 올리는 방식  
스레드(Thread) : CPU가 처리할 수 있는 작업의 단위  

## 네트워크 저장장치
- DAS(Direct Attached Storage) : 서버와 같은 컴퓨터에 직접 연결된 저장장치 (예시 : 윈도우의 파일 공유, 여러 컴퓨터 중 하나를 파일 공유 서버로 지정하고 나머지 컴퓨터에서 서버로 지정된 컴퓨터에 접근하여 파일을 이용하는 방식으로 운영된다.) 컴퓨터에 직접 연결된 저장장치를 사용하기 떄문에 다른 운영체제가 쓰는 파일 시스템을 사용할 수 없다.  
- NAS(Network Attached Storage) : 기존의 저장장치를 LAN이나 WAN(Wide Area Network)에 붙여서 사용하는 방식. NAS는 NAS 전용 운영체제를 가진 독립적인 장치로 새로운 하드디스크를 추가하거나 뺼 수 있다. DAS의 경우 각각의 컴퓨터에 붙어 있기 때문에 공유 데이터의 관리가 힘들고 데이터가 여러 컴퓨터에 중복되어 있는 것이 단점이다. NAS는 이를 보완하기 위해 저장장치를 네트워크상에 두고 여러 클라이언트가 네트워크를 통해 접근하게 함으로써 공유 데이터의 관리 및 데이터의 중복 회피가 가능하다.  
- SAN(Storage Area Network) : NAS보다 진보된 형태의 네트워크 저장장치. NAS가 저장장치에 네트워크 인터페이스를 부착한 형태라면, SAN은 데이터 서버, 백업 서버, RAID 등의 장치를 네트워크로 묶고 데이터 접근을 위한 서버를 두는 형태. SAN에서는 시스템이 제공하는 인터페이스를 통해 데이터를 접근한다. SAN에서는 저장장치에 필요한 장치를 네트워크로 묶어 하나의 시스템을 구성하기 떄문에 다양한 서비스를 제공한다. SAN은 편리하다는 장접이 있는 반면에, 데이터 서버나 백업 서버를 같이 구축하기 때문에 NAS보다 구축 비용이 많이 든다.
RAID(Redundant Array of Independent Disks) : 장애 발생 시 데이터를 복구하기 위해 만든 장치. 값싼 디스크를 병렬로 구성하여 여러 개의 디스크에 데이터를 분산 보관한다.

## 유닉스 파일의 특징
유닉스의 파일 접근 패턴에서 첫 번째 자리를 제외한 나머지 9자리는 rwx라는 세 덩어리로 구성된다. r은 read, w은 write, x는 execute권한을 의미한다.  
첫 번째 덩어리는 파일의 소유자(owner) 권한을, 두 번쨰 덩어리는 소유자가 속한 그룹(group)의 권한을, 세 번째 덩어리는 소유자가 아니고 같은 그룹도 아닌 제3자(others)의 권한을 나타낸다. 유닉스에서는 chmod 명령으로 접근 패턴을 변경할 수 있다. 접근 패턴에 숫자를 부여하여 변경하는데 read : 4, write : 2, execute : 1이며 chmod 명령을 이용하여 살리고 싶은 숫자를 모두 더하면 된다. chmod 777 : rwxrwxrwx, chmod 551 : r-xr-x--x

## 프로토콜
다른 기기 간에 통신을 하기 위해 정한 약속(= 통신규약)
IP(Internet Protocol) : LAN 사이에 데이터 전송을 위한 프로토콜
TCP(Transmission Control Protocol) : IP는 목적지까지 데이터를 보내는 일을 수행했으나 데이터가 원래대로 전달되지 않거나 없어지는 것을 보완하여 개발
TCP/IP : TCP는 IP 위에서 작동하도록 설계되어 만들어진 프로토콜

## 클라우드 컴퓨팅 환경
SaaS(Software as a Service) : 소프트웨어적으로 컴퓨팅 환경을 통합한 것. 사용자가 필요한 스프트웨어 기능만 필요할 떄 이용하고, 이용한 기능만큼만 비용을 지불하는 개념
